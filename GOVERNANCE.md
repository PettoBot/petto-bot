# Governance

Petto is a maintainer-led project. Maintainers are responsible for the
security, compatibility, release quality, and long-term direction of the
official repository.

## Decision process

Features and behavior changes start as an issue or discussion. A maintainer
may request clarification, reject the proposal, or mark it accepted. Only an
accepted proposal or an explicit maintainer invitation authorizes an
implementation pull request.

Maintainers may request design changes, tests, documentation, a smaller scope,
or a staged rollout. A passing CI run does not guarantee acceptance.

## Branches and releases

The default branch is protected. Changes land through reviewed pull requests;
direct pushes, force-pushes, and unreviewed release changes are not part of the
normal workflow. Release notes are maintained by the project and published
with the corresponding release.

## Maintainer authority

Maintainers may close duplicate or unsolicited pull requests, remove unsafe
content, pause features, and revoke contribution access when project safety or
community health requires it. These actions should be explained when doing so
does not increase security risk.
